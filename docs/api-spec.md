# API specification

Base: `/api/v1`. Interactive docs are generated by FastAPI at `/docs`
(disabled in production). This file covers conventions and the planned surface;
the OpenAPI document at `/openapi.json` is authoritative.

## Conventions

- JSON in, JSON out; `snake_case` fields
- Auth: `Authorization: Bearer <access_token>`; refresh via httpOnly cookie
- Timestamps: ISO 8601 UTC with offset (`2026-08-15T09:30:00+00:00`)
- IDs: UUID strings
- `PATCH` for partial updates; unsupplied fields are left unchanged

### Errors

```json
{ "detail": "Application not found" }
```

Validation errors use FastAPI's standard 422 shape.

| Code | Meaning |
|------|---------|
| 400 | Malformed request |
| 401 | Missing/expired token |
| 403 | Authenticated but not the owner |
| 404 | Not found, **or** owned by someone else (deliberate — see below) |
| 409 | Conflict, e.g. email already registered |
| 413 | Upload too large |
| 422 | Validation failed |
| 429 | Rate limited |

Requesting another user's resource returns **404, not 403**. A 403 would confirm the
ID exists, letting an attacker enumerate valid records.

### Pagination

```
GET /applications?page=1&page_size=20
```

```json
{ "items": [], "total": 47, "page": 1, "page_size": 20, "pages": 3 }
```

`page_size` capped at 100.

## Health

```
GET /api/v1/health
```

```json
{
  "status": "ok",
  "version": "0.1.0",
  "environment": "development",
  "database": { "connected": true, "latency_ms": 41.2 }
}
```

Returns **503** with `status: "degraded"` if the database probe fails.
The probe runs a real `SELECT 1`.

## Planned surface

### Auth
```
POST   /auth/register        create account, return tokens
POST   /auth/login           email + password
POST   /auth/refresh         rotate using the httpOnly cookie
POST   /auth/logout          clear the refresh cookie
GET    /auth/me              current user
```

### Users
```
GET    /users/me/profile
PATCH  /users/me/profile
GET    /users/me/skills
POST   /users/me/skills
DELETE /users/me/skills/{id}
DELETE /users/me                 delete account and all data
```

### Applications
```
GET    /applications             ?status= &search= &source= &work_mode= &sort= &page=
POST   /applications
GET    /applications/{id}
PATCH  /applications/{id}
DELETE /applications/{id}
PATCH  /applications/{id}/status  status change + history entry
GET    /applications/board        grouped by status, for the Kanban view
```

### Resumes (planned)
```
GET    /resumes
POST   /resumes                   multipart, PDF only, size-capped
GET    /resumes/{id}
GET    /resumes/{id}/download     short-lived signed access
DELETE /resumes/{id}
```

### Interviews and reminders (planned)
```
GET    /interviews                ?upcoming=true
POST   /interviews
PATCH  /interviews/{id}
DELETE /interviews/{id}

GET    /reminders                 ?completed=false
POST   /reminders
PATCH  /reminders/{id}
DELETE /reminders/{id}

GET    /applications/{id}/notes
POST   /applications/{id}/notes
```

### AI (planned)

Rate limited. Every response is a validated schema, never raw model text.
`provider` and `model` are echoed back so output is traceable.

```
POST   /ai/analyze-job            { job_description } | { application_id }
POST   /ai/analyze-resume         { resume_id, job_description }
POST   /ai/tailor-resume          { resume_id, job_description }
POST   /ai/generate-cover-letter  { resume_id, application_id, tone? }
POST   /ai/interview-questions    { application_id, types[] }
```

`match_score` is ApplyFlow's own transparent skill-overlap metric. It is not an ATS
score and is never described as one.

### Analytics (planned)
```
GET    /analytics/overview        totals, active, offers, rejections
GET    /analytics/conversion      application→interview→offer rates
GET    /analytics/timeline        ?range=30d
GET    /analytics/breakdown       ?by=status|source|work_mode|company
```
